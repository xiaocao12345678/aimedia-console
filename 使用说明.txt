AI 多模态控制台 · 使用说明
====================================

【怎么启动】
双击 AI多模态控制台.exe。这是免安装版（文件夹形式），
整个「AI多模态控制台」文件夹可以复制到任何 Windows 电脑直接运行，不需要装 Python。

【为什么是文件夹而不是单个 exe】
单个 exe 每次启动都要把依赖解压到临时目录，冷启动 3–10 秒。
文件夹形式（onedir）实测 0.70 秒窗口就出来。代价是旁边多一个 _internal 目录，
请把 exe 和 _internal 一起复制，不要只拿 exe。

【配置文件】
同目录的 config.json 保存六家平台 Key 与上次选的模型。
- 有它 → 程序优先用它（便携模式，整个文件夹搬走配置跟着走）
- 没有 → 自动回落到 %APPDATA%\AI多模态控制台\config.json
Key 用 Base64+XOR 混淆，防止肉眼看到/误截图，但不是加密。
想重置：删掉 config.json 重新启动。

【五个标签页】
1. 参考图工作流：参考图 + 需求 → 自动出分析、视频提示词、首帧图 → 可改图改词 → 出视频
2. 图像理解：选图提问，结果可另存
3. 图像生成：文生图 / 图生图，缩略图预览
4. 视频生成：文生视频 / 图生视频
5. 视频编辑：输入参考视频（本地或公网 URL）+ 可选参考图 + 指令 → 生成改好的视频

【首次使用】
1. 点标题栏「平台密钥」，六家平台的 Key 一次填好（每行都有「获取教程」）
2. 顶部下拉选「当前调用哪一家」
3. 「运行日志」按钮打开独立日志窗口：能看到每次请求的 URL、脱敏请求体、响应码、耗时与失败原因

【模型开通（比填 Key 更容易漏的一步）】
拿到 Key 只解决"你是谁"；能不能调某个模型，还看账号有没有开通它。
每个平台的「获取教程」对话框里都有一块蓝色的「模型开通」，写了什么情况会用到、去哪点哪个按钮。
快速对照：
  火山方舟  报 404 ModelNotOpen → 控制台「开通管理」页 → 找到 doubao-seedance/seedream → 点「开通服务」
            （注意：上传文件不需要开通模型，只有生成才需要）
  阿里百炼  模型不存在/未开通 → 模型广场（北京地域）→ 模型详情 → 点「立即开通」
  腾讯混元  报 402 No free trial quota / postpaid billing is not enabled
            → TokenHub 控制台 → 在线推理 → 视觉模型 → 操作列「启用后付费」
  智谱 GLM  不用开通，429 是免费档限流，换付费档
  MiniMax   不用开通，充值即可（402 / base_resp 1008 = 余额不足）
  百度千帆  默认开通，报权限就查 Key 的资源范围
任务失败时程序会直接告诉你属于哪种，并给出对应的控制台地址。

【产物位置】
- 生成的图片 / 视频：本目录 output\
- 运行日志与启动记录：本目录 logs\（startup.log 记录每次启动的配置路径与已配置平台）
- 结果文件命名：img_平台_时间戳.png / vid_平台_时间戳.mp4 / edit_平台_时间戳.mp4

【实测可用情况（2026-10-22，本机账号）】
- 火山方舟：理解、生图可用（Seedream 5.0 一次只出 1 张）；视频编辑需要公网视频 URL
- 阿里百炼：理解、生图可用；视频编辑 wan2.7-videoedit 实测跑通（黏土风格迁移 5s/720P）
- 智谱 GLM：理解（付费档）、生图（cogview-3-flash）、视频（cogvideox-3）可用
            免费档 *-flash 经常 429 限流，不建议做主力；不支持视频输入
- 腾讯混元：理解可用；生图/视频需去 TokenHub 开通后付费（否则 402）；不支持视频输入
- MiniMax：Key 有效但账户余额不足（402），充值后可用；视频编辑支持 base64 本地视频
- 百度千帆：未配置

【出问题了看哪里】
先开「运行日志」窗口，里面是原始请求与平台返回。常见：
  401  → Key 不对 / 填错类型
  402  → 该能力未开通，或余额不足
  404  → 模型没在该账号开通，或模型 ID 写错
  429  → 限流，换付费档或稍后重试
  400  → 参数与模型不匹配（如给某模型传了它不支持的参数）
还不行就看 logs\startup.log 与 logs\app_日期.log。

【重新打包】
项目根目录有 build_exe.cmd，双击即可重新编译（会先清理旧的 build/dist），
打包后会把你当前的配置一起复制进 dist 目录。
